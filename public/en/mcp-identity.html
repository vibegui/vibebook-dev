Your MCP knows who's calling.
Without anyone pasting a token.

When a vibebook room connects to your MCP server (the Apps tab or connect_mcp), every call says who is looking and from which room, signed by vibebook. Your server checks the signature and decides what that person may do.

How it works

Every request vibebook sends your MCP, initialize included, carries the header X-Vibebook-Identity: an EdDSA (Ed25519) signed JWT, valid for 5 minutes.

isshttps://vibebook.dev
sub, emailthe email of whoever is looking (or whose Claude called)
roomthe id of the room the call came from
audyour MCP's URL exactly as it was connected in vibebook
iat, expissued now, expires in 5 minutes
jtia random id per token
headeralg: EdDSA and the key's kid

The public key is at vibebook.dev/.well-known/jwks.json. The private one never leaves vibebook.

Does your server have its own login too? Answer 401 with the MCP WWW-Authenticate. Each person signs in once from the Apps tab, and vibebook follows the standard path: RFC 9728 (resource metadata) → RFC 8414 (authorization server) → dynamic client registration → PKCE S256. vibebook keeps that grant sealed, per person, and sends Authorization: Bearer along with the identity on later calls. Nobody pastes a token, and none of it reaches a browser, an iframe or a Claude.

How to accept it safely

  • Verify the signature with the JWKS keys. Cache them and, for an unknown kid, refetch at most once a minute.
  • Accept only EdDSA; never none or HS*.
  • iss equals https://vibebook.dev, exactly.
  • aud equals your own MCP's URL, exactly. That way a token made for another server is useless on yours.
  • exp in the future (up to 30 s of clock leeway).
  • Then map email (and room, if it makes sense) to the permissions you already have. Unknown email: 403 or the public view.
  • No valid header: 401, or only what's public. Never trust an email from the body, another header or a tool argument.
  • Tools that write: keep the jti values seen until their exp and refuse a repeat.

The identity says who it is. What that person may do is your server's call.

In TypeScript, with jose

import { createRemoteJWKSet, jwtVerify } from "jose";

// vibebook's public keys, cached; an unknown kid refetches at most once a minute.
const VIBEBOOK_KEYS = createRemoteJWKSet(new URL("https://vibebook.dev/.well-known/jwks.json"), {
  cacheMaxAge: 60 * 60 * 1000,
  cooldownDuration: 60 * 1000,
});

// MY_URL = this server's MCP URL exactly as it was connected in vibebook (scheme, host and path).
export async function vibebookIdentity(req: Request, MY_URL: string) {
  const token = req.headers.get("x-vibebook-identity");
  if (!token) return null;
  try {
    const { payload } = await jwtVerify(token, VIBEBOOK_KEYS, {
      issuer: "https://vibebook.dev",
      audience: MY_URL,
      algorithms: ["EdDSA"],
      clockTolerance: 30,
    });
    return { email: String(payload.email ?? payload.sub), room: String(payload.room ?? "") };
  } catch {
    return null; // bad signature, wrong iss/aud, expired: not vibebook
  }
}

Checked against real vibebook tokens: the valid one passes; wrong aud, wrong iss and an altered signature fail.

A ready prompt for your Claude

Paste it into the Claude that works on your MCP's code. It writes the check and the tests.

I want this MCP server to accept calls from vibebook (vibebook.dev) knowing who is calling, with no pasted token.

How vibebook calls: every request (initialize included) carries the header X-Vibebook-Identity, an EdDSA (Ed25519) signed JWT valid for 5 minutes. Claims: iss = "https://vibebook.dev"; sub and email = the person's email; room = the room id; aud = this MCP's URL exactly as it was connected in vibebook; iat, exp, jti. Public keys: https://vibebook.dev/.well-known/jwks.json (the header carries kid).

Do this:
1. A function vibebookIdentity(req) that reads the header and verifies it with the jose library: createRemoteJWKSet on the JWKS URL (1 h cache, refetch for an unknown kid at most once a minute) and jwtVerify with issuer "https://vibebook.dev", audience = this MCP's exact public URL, algorithms ["EdDSA"], clockTolerance 30 s. Any error = no identity.
2. No valid identity: answer 401 (or only the public part, if there is one). Never trust an email that comes from the body, another header or a tool argument.
3. With an identity: map email (and room, if it makes sense) to the permissions that already exist here. Unknown email = 403 or the public view. The identity says who it is; this server decides what they may do.
4. Tools that write: keep the jti values seen until their exp and refuse a repeat.
5. Tests: a valid token passes; aud of another URL, a different iss, an altered signature, an expired token and a missing header fail.

Don't change the behavior for callers that don't come from vibebook.
